✍️ 첫 번째 글 · Day 1

부끄러웠지만 AI에게 물어봤다. "코딩이 머야?"

2025년 2월 19일 · 잼미니

오늘 처음으로 AI한테 물어봤다. "코딩이 머야?" 타이핑하면서도 좀 부끄러웠다. 이런 것도 모르면서 앱을 만들겠다고 한 건가 싶기도 하고.

"코딩이란 컴퓨터한테 일을 시키는 특별한 언어예요."

AI가 이렇게 알려줬다. 생각보다 엄청 어렵거나 무서운 개념이 아니었다. 우리가 일상에서 쓰는 유튜브, 카카오톡, 쇼핑몰... 이 모든 게 다 누군가가 코딩으로 만든 것이라고 했다. 그 말을 듣고 나니 왠지 모르게 가슴이 두근거렸다.

코딩 언어도 여러 종류가 있는데, 입문자한테는 Python(파이썬)이 제일 좋다고 했다. 하지만 나는 일단 웹사이트부터 만들어보고 싶었다. 그래서 HTML부터 시작하기로 했다.

"코딩을 몰라도 AI와 함께라면 만들 수 있다."

그리고 놀라운 일이 일어났다. AI가 오늘 이 대화를 하면서 — 그러니까 지금 내가 처음으로 코딩에 대해 물어보는 이 순간을 기록하는 블로그를 바로 만들어줬다. 이게 바로 이 페이지다.

코딩도 모르는 내가, AI와 함께, 진짜 웹사이트를 보고 있다. 이게 무슨 일인지 아직도 실감이 잘 안 나지만... 일단 시작은 했다. 다음 글에선 HTML이 뭔지 알아볼 예정이다.

# 오늘 배운 것
코딩 = 컴퓨터에게 일을 시키는 언어
AI = 코딩 모르는 나의 선생님이자 파트너
나 = 이제 막 시작한 초보 중의 초보

부끄럽지만, 이 블로그가 언젠가 나처럼 코딩이 두려운 누군가에게 작은 용기가 되길 바란다. 🌱

😅 좌충우돌 실전기 · Day 2

HTML도 모르는데 블로그가 인터넷에 떴다

2026년 2월 20일 · 느린 개발자

솔직히 말하면, 나는 아직도 HTML이 정확히 뭔지 모른다. 근데 지금 이 블로그는 인터넷에 떠 있다. 어떻게 된 일인지 나도 좀 어리둥절하다. 😅

몰라도 일단 실행!

AI가 블로그를 만들어줬다. 코드라는 게 화면에 쭉 나왔는데 뭔 말인지 하나도 모르겠더라. 근데 AI가 "이거 복사해서 GitHub에 붙여넣으세요" 라고 했다. GitHub? 그게 또 뭐야.

알고 보니 GitHub는 코드를 저장하는 창고 같은 거란다. 그리고 Netlify는 그 창고에 있는 코드를 인터넷에 올려주는 배달부 같은 거고. 50 넘어서 처음 듣는 단어들이 줄줄이 나왔다. 당황스러웠지만 일단 가입부터 했다.

아이패드로 하다가 생고생!

처음엔 아이패드로 작업했다. 코드를 복사해서 GitHub에 붙여넣었는데 — 나중에 블로그를 열어보니 디자인이 완전히 박살나 있었다. 알고 보니 아이패드가 코드 안의 특수문자를 자기 마음대로 바꿔버린 거였다. 예를 들어 코드에서 중요한 역할을 하는 -- 가 – 로 바뀌어버리는 식으로. 눈으로 봐선 거의 차이가 없는데 컴퓨터는 완전히 다르게 인식한다.

이게 바로 코딩의 세계다. 사람 눈엔 똑같아 보여도 컴퓨터한테는 전혀 다른 말이 되어버리는 것. 50대 초보한테는 꽤 충격적인 경험이었다.

컴퓨터로 한방에 해결!

결국 컴퓨터 앞에 앉았다. 파일을 다운로드해서 Netlify에 드래그앤드롭. 그리고 URL 이름을 slowdeveloper 로 지정했다. 그러자 slowdeveloper.netlify.app 이라는 주소가 생겼고, 블로그가 예쁘게 떴다.

아이폰으로 그 주소를 입력해봤다. 진짜 열렸다. 인터넷 어디서나 접속할 수 있는 내 블로그가 생긴 것이다. HTML이 뭔지도 모르면서.

같은 실수는 No!

나 같은 중년 초보들에게 당부하고 싶다. 아이패드로 코딩 작업하다 보면 이런 자동변환 함정에 빠지기 쉽다. 설정 → 일반 → 키보드 → 스마트 구두점을 꼭 꺼두자. 아니면 처음부터 컴퓨터로 하는 게 속편하다.

모르는 게 부끄러운 게 아니다. 모르면 물어보면 된다. AI한테. 그리고 틀려도 괜찮다. 나는 오늘도 여러 번 틀렸고, 그러면서 조금씩 알아가고 있다. 느려도 괜찮다. 어차피 나는 느린 개발자니까. 🌱

# 오늘 배운 것
GitHub = 코드 저장 창고
Netlify = 창고 코드를 인터넷에 올려주는 배달부
아이패드 자동고침 = 코딩의 적
결론 = 모르면 AI한테 물어보고, 컴퓨터로 하자
🤦 삽질 기록 · Day 3

개념을 모르니 업로드 하나도 쉽지 않네!

2026년 2월 22일 · 느린 개발자

드디어 컴퓨터 앞에 앉았다. 아이패드로 고생한 이후라 이번엔 좀 쉽게 될 줄 알았다. 파일 하나 올리면 되는 거 아닌가? 그게 아니었다. 😅

파일? 아니, 폴더!

Netlify에 파일을 드래그앤드롭 하려고 했더니 파일이 아니라 폴더로 올려야 한다고 나왔다. 황당했다. 파일 하나인데 왜 폴더가 필요하지? 알고 보니 이유가 있었다.

Netlify는 웹사이트 전체를 하나의 폴더로 관리한다. 지금은 파일이 하나뿐이지만, 나중에 이미지, 글 파일 등이 늘어나면 모두 이 폴더 안에 들어가게 된다. 그래서 처음부터 폴더째로 올리는 방식을 쓰는 것이다. 미래를 대비한 구조인 셈이다.

index.html, 이름이 왜 중요해?

또 하나 당황스러운 게 있었다. AI가 만들어준 파일 이름은 slow-developer.html 인데, 이걸 반드시 index.html 로 바꿔야 한다고 했다.

왜냐고? 누군가 slowdeveloper.netlify.app 에 접속하면, 컴퓨터가 폴더 안에서 자동으로 index.html 이라는 이름의 파일을 찾아서 보여준다. 이건 인터넷의 오래된 약속이다. 이 이름이 아니면 화면이 안 열린다.

앞으로 업로드 방법은?

이제 앞으로 블로그를 갱신할 때마다 이렇게 하면 된다는 걸 알았다.

AI한테 수정된 파일을 받는다 → 파일 이름을 index.html 로 바꾼다 → Netlify Deploys 영역에 드래그앤드롭. 끝이다. 매번 똑같은 과정이다.

참고로 업로드 방식은 두 가지다. 폴더째로 올려도 되고, 파일을 여러 개 선택해서 올려도 된다. 둘 다 된다. 나는 처음에 폴더째로 올리다가 확장자가 두 번 붙는 황당한 오류를 겪었다. 파일을 직접 선택해서 올리는 게 더 안전할 수 있다.

실수도 다 기록으로 남긴다!

처음엔 이게 왜 이렇게 복잡하게 느껴졌는지 모르겠다. 개념을 모르니까 당연히 막혔던 거다. 알고 나면 별거 아닌데, 모를 때는 산처럼 느껴진다. 50대 초보의 현실이다. 이 블로그는 성공담만 쓰는 게 아니라 이런 황당한 실수들도 다 기록한다. 나 같은 초보에게 더 도움이 될 테니까. 😄

# 앞으로 블로그 갱신 순서
1. AI한테 수정 요청
2. 파일 다운로드
3. 파일 이름 → index.html 로 변경
4. Netlify Deploys 영역에 드래그앤드롭
   (폴더째로 or 파일 선택해서 — 둘 다 OK)
5. Published 확인 → 완료!

모르면 막히고, 알면 간단하다. 오늘도 한 걸음 앞으로. 🌱

🎵 감성 추가 · Day 4

블로그에 배경음악을 넣다!

2026년 2월 23일 · 느린 개발자

블로그를 만들고 나니 욕심이 생겼다. 이왕이면 배경음악도 있으면 좋겠다 싶었다. 코딩도 모르는 내가 배경음악까지 넣을 수 있을까? 역시나 AI한테 물어봤다.

저작권, 먼저 확인!

AI가 제일 먼저 한 말이 저작권 얘기였다. 유명 음악을 블로그에 그냥 쓰면 법적 문제가 생길 수 있다고. 그래서 저작권이 만료된 클래식 음악을 쓰는 게 가장 안전하다고 했다. 작곡가가 사망한 지 70년이 지나면 저작권이 없어진다고 한다. 바흐, 베토벤, 쇼팽 같은 음악들이 다 해당된다.

무료 음악은 여기서!

AI가 추천해준 사이트는 musopen.org 였다. 클래식 음악 전문 무료 사이트인데, 음질도 좋고 종류도 다양했다. 블로그 분위기에 맞는 곡으로 드뷔시의 달빛 (Clair de Lune) 을 골랐다. 도시적이면서도 따뜻한 느낌이 딱 맞았다.

파일 이름은 짧게!

다운로드 받은 파일 이름이 엄청 길었다. 23843807-clair-de-lune-suite-bergamasque... 이런 식으로. AI가 짧게 바꾸라고 했다. 긴 파일 이름은 코딩에서 오류를 일으킬 수 있다고. clair-de-lune.mp3 로 바꿨다.

그 다음 AI가 코드를 수정해줬다. 화면 오른쪽 하단에 🎵 버튼이 생겼고, 누르면 음악이 재생되고 🔊 로 바뀐다. 끄면 다시 🎵 로 돌아온다.

음악 파일도 같이 올려야!

여기서 또 한 가지 배웠다. Netlify에 올릴 때 index.html 파일만 올리면 안 된다. 음악 파일 clair-de-lune.mp3 도 같이 올려야 소리가 난다. 두 파일을 함께 선택해서 Netlify에 드래그앤드롭 하면 끝!

이제 이 블로그엔 드뷔시 달빛이 흐른다. 코딩도 모르는 50대가 배경음악까지 넣었다. AI 없이는 절대 못 했을 일이다. 느려도 하나씩 되어가고 있다. 🌱

다음엔 블로그에 사진도 넣어보고, 디자인도 좀 바꿔보고 싶다. 지금 디자인도 나쁘지 않지만, 내 손으로 직접 뭔가를 바꿔보는 경험을 해보고 싶다. 과연 잘 될까? 또 어떤 좌충우돌이 기다리고 있을지 벌써부터 걱정 반 기대 반이다. 😄

📅 드디어 달력! · Day 5

HTML, CSS, JavaScript — 웹의 3총사를 만나다

2026년 2월 24일 · 느린 개발자

드디어 이 블로그의 최종 목표인 가족 스케줄 달력을 만들기 시작했다. 그런데 달력을 만들면서 처음으로 낯선 단어 두 개를 제대로 만났다. CSS와 JavaScript. 도대체 이게 뭔지 AI한테 물어봤다.

웹사이트는 3총사로 만든다!

AI가 아주 쉽게 설명해줬다. 웹사이트는 세 가지 언어로 이루어진다고.

HTML은 뼈대다. 달력의 칸, 날짜 숫자, 버튼 같은 구조를 만든다. 사람으로 치면 몸의 뼈와 근육이다.

CSS는 옷이다. 달력 배경색, 글자 크기, 버튼 모양 같은 디자인을 담당한다. 뼈대에 예쁜 옷을 입히는 것이다.

JavaScript는 행동이다. ◀ 버튼을 누르면 전달로 이동하고, 날짜를 클릭하면 팝업이 뜨는 것 — 이런 모든 움직임을 담당한다.

달력 기능, 생각보다 많네!

달력 하나를 만드는 데 이렇게 많은 게 들어갈 줄 몰랐다. AI가 만들어준 달력에는:

양력 날짜는 기본이고 음력 날짜도 작게 표시된다. 한국 공휴일은 빨간색, 일본 공휴일은 주황색으로 구분된다. 오늘 날짜는 금색으로 강조된다. 날짜를 클릭하면 일정 추가 팝업이 열린다. 아빠/엄마/아들 구성원별로 색깔이 다른 점으로 일정이 표시된다.

코딩을 몰라도 만들어진다!

솔직히 CSS나 JavaScript 코드를 보면 아직도 무슨 말인지 모르겠다. 근데 신기한 건, 몰라도 만들어진다는 것이다. AI한테 "달력 만들어줘, 음력도 넣어줘, 공휴일도 표시해줘" 라고 말하면 AI가 다 알아서 코드로 만들어준다.

내가 할 일은 결과물을 보고 "이건 좋다, 이건 바꾸자" 라고 말하는 것뿐이다. 마치 인테리어 업자한테 "이 벽은 흰색으로, 저 벽은 파란색으로" 지시하는 것처럼. 코딩을 몰라도 방향을 잡고 지시할 수 있다면 충분하다.

다음엔 로그인 기능을 넣어서 가족만 일정을 수정할 수 있게 만들어볼 예정이다. 또 어떤 좌충우돌이 기다리고 있을지 — 느린 개발자의 도전은 계속된다. 🌱

# 웹사이트 3총사 정리
HTML = 뼈대 (구조)
CSS = 옷 (디자인)
JavaScript = 행동 (움직임)

# 핵심 깨달음
코딩을 몰라도 방향만 잡으면 AI가 만들어준다!
📸 달력 진화 중 · Day 6

달력에 가족 사진을 입히다!

2026년 3월 2일 · 느린 개발자

달력을 만들고 나서 바로 여러 문제들이 발견됐다. 음력이 틀리고, 공휴일 색이 비슷하고, 사진도 안 들어가고. 하나씩 고쳐나갔다.

음력 날짜가 틀렸다!

2026년 2월 17일이 음력 1월 1일 구정인데, 달력에는 2월 18일로 나왔다. 하루가 틀린 거다. 이건 내가 발견한 게 아니라 직접 써보면서 알게 됐다. AI한테 수정 요청했더니 2026년 전체 음력 데이터를 정확하게 교체해줬다. 이제 구정, 초하루, 보름 같은 특별한 날도 제대로 표시된다.

공휴일 색 구분!

한국 공휴일과 일본 공휴일이 둘 다 빨간색 계열이라 구분이 잘 안 됐다. 한국은 빨간색, 일본은 파란색으로 바꿨다. 이제 한눈에 구분된다.

사진이 달력 배경으로!

처음엔 사진을 달력 위에 따로 배치했는데, 달력 배경으로 깔고 그 위에 날짜를 표시하는 방식으로 바꿨다. 사진이 너무 진하면 숫자가 안 보이니까 반투명 흰색 레이어를 얹었다. 12달 사진을 모두 준비해서 매달 다른 가족 사진이 배경으로 나온다.

Netlify에서 GitHub Pages로 이전!

Netlify 무료 플랜 용량을 초과해버렸다. 사진과 음악 파일이 많아지면서 대역폭을 너무 많이 썼다. GitHub Pages로 이전했다. GitHub 저장소에 파일을 업로드하고 Settings에서 Pages를 활성화하면 끝. URL이 조금 길어졌지만 완전 무료에 용량도 넉넉하다.

그리고 모바일에서 홈 화면 사진이 안 보이는 문제도 발견해서 수정했다. PC에서는 잘 보이는데 스마트폰에서는 숨겨져 있었다. CSS 코드 한 줄 때문이었다. 이런 게 바로 코딩의 세계다. 눈에 안 보이는 작은 설정 하나가 전혀 다른 결과를 만든다.

달력이 점점 진짜 앱처럼 되어가고 있다. 느리지만, 분명히 나아가고 있다. 🌱
